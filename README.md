# GoPassGen

![Version](https://img.shields.io/badge/version-1.4.1-green) ![Go](https://img.shields.io/badge/go-1.21+-green) ![Compatible](https://img.shields.io/badge/compatible-PyPassGen%201.3.5-blue) ![Coverage](https://img.shields.io/badge/coverage-93.2%25-green)

**GoPassGen** generates deterministic passwords from BIP-39 mnemonic phrases, or automatically creates mnemonic phrases and passwords. It is a Go port of [PyPassGen](https://github.com/cyberanchor/pypassgen) and produces **byte-identical passwords** for the same mnemonic.

## ⚠️ Compatibility notice

GoPassGen implements the **PyPassGen v1.3.5** derivation algorithm (`derivation: pypassgen-1.3.5`, printed by `-version`). The same mnemonic yields the same password in both tools:

```console
$ python3 pypassgen.py --mnemonic "$M" --password-length 24 2>/dev/null
zc(zuzq5gYWa%diT#-:^Fx3o
$ gopassgen -mnemonic "$M" -password-length 24
zc(zuzq5gYWa%diT#-:^Fx3o
```

Passwords generated by PyPassGen **≤ 1.3.3 will NOT match** — that break happened upstream, before this port existed.

## Features
- **Mnemonic generation**: BIP-39 phrases in 7 languages (English, French, Spanish, Italian, Japanese, Korean, Chinese Simplified);
- **Deterministic passwords**: PBKDF2-HMAC-SHA512 with 1,000,000 iterations, bit-compatible with PyPassGen 1.3.5;
- **Customizable**: password lengths up to 256 characters, up to 100 pairs per run, up to 10,000 mnemonics;
- **File output**: saves mnemonics and passwords in mnemonic-password format, with `0600` permissions;
- **Entropy reporting**: logs both the charset upper bound and the effective entropy capped by the mnemonic;
- **Parallel processing**: worker pool for batch generation, with clean `Ctrl-C` cancellation;
- **Built-in self test**: `-self-test` runs seven known-answer checks against the reference vectors;
- **Single static binary**: no runtime, no interpreter, no shared libraries, no build metadata.

## Cryptographic architecture
- **Mnemonic to seed**: NFKD-normalized phrase → PBKDF2-HMAC-SHA512, salt `"mnemonic"`, 2048 iterations, 64 bytes;
- **Key derivation**: seed → PBKDF2-HMAC-SHA512, fixed salt `"0"`, 1,000,000 iterations, 64 bytes;
- **Password generation**: HMAC-SHA512 stream keyed by that key over `"PyPassGen\x00" || counter_be32`, mapped to an 88-character alphabet by rejection sampling (bytes ≥ 176 discarded, so there is no modulo bias);
- **Entropy**: `H = log2(N^C)` with N=88, reported alongside the mnemonic's own entropy;
- **Memory safety**: seeds, keys and passwords are handled as `[]byte` and zeroed after use.

Full specification, including every byte that matters:

```
1. m    = NFKD(mnemonic)
2. seed = PBKDF2-HMAC-SHA512(pw = m,    salt = "mnemonic", iter = 2048,    dkLen = 64)
3. key  = PBKDF2-HMAC-SHA512(pw = seed, salt = "0",        iter = 1000000, dkLen = 64)
4. blk_i = HMAC-SHA512(key, "PyPassGen\x00" || uint32be(i)),  i = 0, 1, 2, ...
5. accept stream byte b if b < 176; character = CHARSET[b % 88]

CHARSET = "abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789"
        + "!@#$%^&*()_+-=[]{};:,.<>?~"
```

## Installation

### From a release

```bash
VER=1.4.1
OS=linux ARCH=amd64            # or darwin/arm64, windows/amd64, ...
BASE=gopassgen-v${VER}-${OS}-${ARCH}

curl -LO "https://github.com/<user>/gopassgen/releases/download/v${VER}/${BASE}.zip"
curl -LO "https://github.com/<user>/gopassgen/releases/download/v${VER}/SHA256SUMS"

sha256sum --ignore-missing -c SHA256SUMS     # verify before unpacking
unzip "${BASE}.zip" && cd "${BASE}"
sha256sum -c gopassgen.sha256                # verify the binary itself
chmod +x gopassgen && ./gopassgen -self-test
```

The binary is static and standalone: no Go toolchain, no libc dependency, nothing to install.

### From source

```bash
git clone https://github.com/<user>/gopassgen
cd gopassgen
./build.sh release          # -> build/gopassgen
./build.sh --help           # all build modes
```

Dependencies are vendored, so the build needs no network access.

## Usage

### Command-line arguments
- `-mnemonic <phrase>`: BIP-39 mnemonic phrase to derive a password from;
- `-mnemonic-stdin`: read the phrase from stdin instead (keeps it out of shell history and `ps`);
- `-auto-gen`: auto-generate mnemonic phrases and passwords;
- `-mnemonic-only`: generate only valid BIP-39 mnemonics (no passwords);
- `-phrases <N>`: number of pairs for `-auto-gen` (default: 1, max: 100);
- `-count <N>`: number of mnemonics for `-mnemonic-only` (default: 1, max: 10,000). If `N > 1000`, `-output` is required;
- `-words <N>`: words per phrase (12, 15, 18, 21, 24; default: 12);
- `-password-length <N>`: password length (default: 12, max: 256);
- `-language <lang>`: mnemonic language (default: english);
- `-output <file>`: save output to a file, created with mode `0600`;
- `-jobs <N>`: parallel derivations (default: number of CPUs);
- `-log-level <lvl>`: `silent|error|warn|info|debug` (default: info);
- `-log-format <fmt>`: `pretty|json` (default: pretty);
- `-v`, `-verbose`: shorthand for `-log-level debug`;
- `-no-color`: disable ANSI colour in logs;
- `-self-test`: run built-in known-answer tests and exit;
- `-version`: print version, derivation version and runtime, then exit.

Both `-flag` and `--flag` are accepted.

### Examples

1. Generate a password from a mnemonic:
   ```bash
   gopassgen -mnemonic "expire join uncover ..." -password-length 16
   ```
   **Output**:
   ```
   BsZwx:(36vBaSD^y
   ```
   Only the password reaches stdout, so it pipes cleanly:
   ```bash
   gopassgen -mnemonic-stdin < phrase.txt | wl-copy
   ```

2. Auto-generate 3 phrases with 24 words and 32-character passwords:
   ```bash
   gopassgen -auto-gen -phrases 3 -words 24 -password-length 32 -output phrases.txt
   ```
   **Output**:
   ```
   Mnemonic 1: polar ready danger stumble ... suffer venue
   Password 1: BsZwx:(36vBaSD^y4cg+H6e#]0p#(7iU

   Mnemonic 2: unaware they elder convince ... kind chalk
   Password 2: C0_M{fYrtiT;uZ2<0vmhcrr&}RKhjIl@
   ```

3. Generate a French mnemonic with a 20-character password:
   ```bash
   gopassgen -auto-gen -language french -password-length 20
   ```

4. Generate mnemonics only:
   ```bash
   gopassgen -mnemonic-only                                        # 1 phrase, 12 words
   gopassgen -mnemonic-only -count 200 -words 24 -language french  # to stdout
   gopassgen -mnemonic-only -count 5000 -words 24 -output list.txt # -output required above 1000
   ```

5. Verify the binary does what it claims:
   ```bash
   gopassgen -self-test
   ```
   ```
   PASS alphabet     size=88 duplicates=0 rejection-limit=176
   PASS wordlists    7 wordlists verified against SHA-256 digests
   PASS nfkd         ideographic space folds to U+0020
   PASS bip39-seed   PBKDF2-HMAC-SHA512 2048 iterations
   PASS stream       HMAC-SHA512 stream + rejection sampling
   PASS kdf          PBKDF2-HMAC-SHA512 1000000 iterations
   PASS end-to-end   mnemonic to password, PyPassGen 1.3.5 vector
   ```

## Password entropy

Entropy measures password strength in bits (`H = log2(N^C)`, N=88). GoPassGen logs it in DEBUG mode, together with the effective value.
- **Examples**:
  - 12 characters: ~77.5 bits
  - 16 characters: ~103.4 bits
  - 32 characters: ~206.7 bits
- **Guidelines**:
  - `< 64 bits`: Weak
  - `64–80 bits`: Minimum
  - `80–128 bits`: Good
  - `> 128 bits`: Excellent

**The charset bound is an upper bound only.** A password derived from a 12-word mnemonic carries at most 128 bits regardless of its length, because that is all the entropy the phrase has. A 256-character password from a 12-word phrase is still a 128-bit secret. `-verbose` prints both numbers.

## File output format

With `-output <file>`, `-auto-gen` saves in this format:

```
mnemonic1
password1
mnemonic2
password2
```

`-mnemonic-only` writes one mnemonic per line. Files are created with mode `0600`
(the Python original used the default `0644`).

## Logging

Diagnostics are emitted through the standard library's `log/slog` with structured attributes, so every value is a real key rather than text baked into a sentence:

```console
$ gopassgen -mnemonic-only -count 2 -words 24 -v
2026-08-12 11:59:40.002 - DEBUG - starting language=english version=1.4.0 derivation=pypassgen-1.3.5
2026-08-12 11:59:40.003 - DEBUG - wordlist loaded language=english words=2048
2026-08-12 11:59:40.003 - INFO  - generating mnemonics language=english count=2 words=24
```

`-log-format json` switches to `slog.JSONHandler` for machine consumption, which is the practical mode for large batches:

```console
$ gopassgen -auto-gen -phrases 50 -log-format json 2>run.jsonl
$ jq 'select(.level=="DEBUG") | .stats.rejected' run.jsonl
```

Colours are enabled only when stderr is a TTY. Redirecting or piping output disables ANSI codes automatically, and `NO_COLOR` or `-no-color` disables them unconditionally. Logs go to **stderr**, generated output to **stdout**, so redirection never mixes the two.

The pretty layout is a small custom `slog.Handler`; attribute and group handling is delegated to `slog.TextHandler`, and the handler is verified against `testing/slogtest`, the standard library's own conformance suite.

## Building

```bash
./build.sh release              # static, stripped, no build id -> build/gopassgen
./build.sh debug                # symbols + DWARF, -N -l, for delve
./build.sh check                # gofmt + go vet + short tests
./build.sh test                 # full suite, including all compatibility vectors
./build.sh verify-reproducible  # build twice, compare SHA-256
./build.sh dist                 # cross-compile every target, zip, checksum
./build.sh clean
```

| | release | debug |
|---|---|---|
| symbol table | stripped (`-s`) | kept |
| DWARF | stripped (`-w`) | kept |
| Go build ID | cleared (`-buildid=`) | cleared |
| VCS stamping | off (`-buildvcs=false`) | off |
| paths | trimmed (`-trimpath`) | absolute |
| optimisation | default | disabled (`-gcflags=all=-N -l`) |
| CGO | disabled (static) | disabled (static) |

Release builds are **reproducible**: the same source tree and Go version produce the same SHA-256 on any machine, in any directory. Verify with `./build.sh verify-reproducible`.

### What is and is not in a release binary

Removed: the Go build ID, VCS stamping (revision, branch, dirty flag), absolute source paths, the symbol table and DWARF debug information. No timestamps are embedded, and no version string is injected at link time — the version is a source constant, which is what makes the output deterministic.

Still present, because Go has no supported way to remove it: the standard build-info block that `go version -m` reads — module path, dependency versions (`golang.org/x/crypto`, `golang.org/x/text`) and build flags such as `GOOS`/`GOARCH`/`CGO_ENABLED`. It contains nothing about the machine that built it. Inspect it yourself:

```console
$ go version -m gopassgen
gopassgen: go1.22.2
        path    gopassgen/cmd/gopassgen
        build   -trimpath=true
        build   CGO_ENABLED=0
        ...
$ go tool buildid gopassgen      # empty: no build id
$ strings gopassgen | grep /home # nothing: no paths
```

## Testing

```bash
./build.sh test              # everything
go test -short ./...         # fast, skips the 1M-iteration vectors
go test -race ./...          # concurrency checks
go test -cover ./...         # coverage
```

The suite includes **22 end-to-end password vectors** across all seven languages and lengths 1/12/16/24/32/100/256, plus 35 mnemonic-encoding vectors, 15 seed vectors and 18 validation edge cases — all generated by the Python reference implementation and stored in `internal/passgen/testdata/vectors.json`. **A failing vector means the build is wrong; never edit a vector to make it pass.**

Coverage is 93.2% of statements (only `main()` and the signal-handling wrapper are below target, plus self-test failure branches that are unreachable in an intact binary).


## Security notes

**Best-effort memory wiping.** Seeds, keys and passwords are zeroed after use, but Go's garbage collector may have copied them beforehand. This is the same limitation the Python original documents, and it cannot be fully solved without locked, non-movable memory.

**Errors never echo the phrase.** A rejected mnemonic produces a message naming the *position* of the bad word, never the word itself, so logs and terminal scrollback stay clean. The same applies to `-verbose` in either format: it reports timings, byte counts and rejection rates, never key material. A test asserts that no word of the mnemonic and no character of the password appears in debug output.

**Prefer `-mnemonic-stdin`.** Passing a phrase as `-mnemonic` puts it in shell history and makes it visible in `ps` to every user on the machine.

**Whitespace is significant.** A mnemonic with a double space, a tab or a leading space is rejected, exactly as in the Python implementation. GoPassGen deliberately does not "repair" such input: trimming it would hash a different byte string and silently produce a different password.

### Known properties of the algorithm

These are inherited from the PyPassGen format and preserved for compatibility. They are documented rather than fixed, because fixing them would change every existing password:

- **Shorter passwords are prefixes of longer ones.** The 12-character password is exactly the first 12 characters of the 32-character one from the same phrase, since both consume the same stream. Leaking a short password reveals the start of a long one.
- **One phrase, one password.** There is no per-site separation: the domain-separation input exists in the format but is always empty. A separate mnemonic per site is the only isolation available.
- **The 1,000,000 PBKDF2 iterations add little.** They stretch a 512-bit seed that is already unguessable; stretching defends low-entropy inputs, and this input is not one. Real strength equals the mnemonic's entropy: 128 bits for 12 words, 256 for 24.
