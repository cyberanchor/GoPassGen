# GoPassGen

![Version](https://img.shields.io/badge/version-1.5.0-green) ![Go](https://img.shields.io/badge/go-1.26+-green) ![Compatible](https://img.shields.io/badge/compatible-PyPassGen%201.3.5-blue) ![Coverage](https://img.shields.io/badge/coverage-95%25-green)

**GoPassGen** generates deterministic passwords from BIP-39 mnemonic phrases, or automatically creates mnemonic phrases and passwords. It is a Go port of [PyPassGen 1.3.5](https://github.com/cyberanchor/pypassgen/tree/v1.3.5-stability) and produces **byte-identical passwords** for the same mnemonic.

## ⚠️ Compatibility notice

GoPassGen implements the **PyPassGen v1.3.5** derivation algorithm (`derivation: pypassgen-1.3.5`, printed by `-version`). The same mnemonic yields the same password in both tools:

```console
$ M="abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon about"
$ python3 pypassgen.py --mnemonic "$M" --password-length 24 2>/dev/null
Generated Password: ,6UiYsb-haPxbRcv=K5%).Mf
$ gopassgen -mnemonic "$M" -password-length 24 2>/dev/null
,6UiYsb-haPxbRcv=K5%).Mf
```

The compatible Python code is on the [`v1.3.5-stability` branch](https://github.com/cyberanchor/pypassgen/tree/v1.3.5-stability). The default `main` branch of that repository holds version 1.3.0, which uses another algorithm and produces different passwords.

Passwords generated by PyPassGen **≤ 1.3.3 will NOT match** — that break happened upstream, before this port existed.

## Features
- **Mnemonic generation**: BIP-39 phrases in 7 languages (English, French, Spanish, Italian, Japanese, Korean, Chinese Simplified);
- **Deterministic passwords**: PBKDF2-HMAC-SHA512 with 1,000,000 iterations, bit-compatible with PyPassGen 1.3.5;
- **Customizable**: password lengths up to 256 characters, up to 100 pairs per run, up to 10,000 mnemonics;
- **File output**: saves mnemonics and passwords to an ordinary file that only appears once it is complete;
- **Entropy reporting**: logs both the charset upper bound and the effective entropy capped by the mnemonic;
- **Parallel processing**: worker pool for batch generation, with clean `Ctrl-C` cancellation;
- **Built-in self test**: `-self-test` runs seven known-answer checks against the reference vectors;
- **Single static binary**: no runtime, no interpreter, no shared libraries.

## Cryptographic architecture
- **Mnemonic to seed**: NFKD-normalized phrase → PBKDF2-HMAC-SHA512, salt `"mnemonic"`, 2048 iterations, 64 bytes;
- **Key derivation**: seed → PBKDF2-HMAC-SHA512, fixed salt `"0"`, 1,000,000 iterations, 64 bytes;
- **Password generation**: HMAC-SHA512 stream keyed by that key over `"PyPassGen\x00" || counter_be32`, mapped to an 88-character alphabet by rejection sampling (bytes ≥ 176 discarded, so there is no modulo bias);
- **Entropy**: `H = log2(N^C)` with N=88, reported alongside the mnemonic's own entropy;
- **Memory safety**: seeds, keys, HMAC state, entropy and passwords are handled as `[]byte` and zeroed after use, within the limits described under [Security notes](#security-notes).

Full specification, including every byte that matters:

```
1. m    = NFKD(mnemonic)
2. seed = PBKDF2-HMAC-SHA512(pw = m,    salt = "mnemonic", iter = 2048,    dkLen = 64)
3. key  = PBKDF2-HMAC-SHA512(pw = seed, salt = "0",        iter = 1000000, dkLen = 64)
4. blk_i = HMAC-SHA512(key, "PyPassGen\x00" || uint32be(i)),  i = 0, 1, 2, ...
5. accept stream byte b if b < 176; character = CHARSET[b % 88]

CHARSET = "abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ0123456789"
        + "!@#$%^&*()_+-=[]{};:,.<>?~"
```

## Installation

### With Go

```bash
go install github.com/cyberanchor/GoPassGen/cmd/gopassgen@latest
gopassgen -self-test
```

This needs Go 1.26 or newer.

### From a release

Each [release](https://github.com/cyberanchor/GoPassGen/releases) carries a prebuilt binary for Linux x86-64, the source archive and `SHA256SUMS`. On other systems use `go install` or build from source. Windows is not built or tested.

```bash
VER=1.5.0
BASE=gopassgen-v${VER}-linux-amd64

curl -LO "https://github.com/cyberanchor/GoPassGen/releases/download/v${VER}/${BASE}.zip"
curl -LO "https://github.com/cyberanchor/GoPassGen/releases/download/v${VER}/SHA256SUMS"

sha256sum --ignore-missing -c SHA256SUMS     # verify before unpacking
gh attestation verify "${BASE}.zip" --repo cyberanchor/GoPassGen   # signed build provenance
unzip "${BASE}.zip" && cd "${BASE}"
sha256sum -c gopassgen.sha256                # verify the binary itself
chmod +x gopassgen && ./gopassgen -self-test
```

The binary is static and standalone: no Go toolchain, no libc dependency, nothing to install. The archive also holds `README.md`, `CHANGELOG.md`, `LICENSE` and, in `licenses/`, the licenses of the bundled Go code.

### From source

```bash
git clone https://github.com/cyberanchor/GoPassGen
cd GoPassGen
./build.sh release          # -> build/gopassgen
./build.sh --help           # all build modes
```

Dependencies are vendored, so the build needs no network access.

## Usage

### Command-line arguments
- `-mnemonic <phrase>`: BIP-39 mnemonic phrase to derive a password from;
- `-mnemonic-stdin`: read the phrase from stdin instead (keeps it out of shell history and `ps`);
- `-auto-gen`: auto-generate mnemonic phrases and passwords;
- `-mnemonic-only`: generate only valid BIP-39 mnemonics (no passwords);
- `-phrases <N>`: number of pairs for `-auto-gen` (default: 1, max: 100);
- `-count <N>`: number of mnemonics for `-mnemonic-only` (default: 1, max: 10,000). If `N > 1000`, `-output` is required;
- `-words <N>`: words per phrase (12, 15, 18, 21, 24; default: 12);
- `-password-length <N>`: password length (default: 12, max: 256);
- `-language <lang>`: mnemonic language (default: english);
- `-output <file>`: write the result to a file instead of stdout, in every mode (see [File output](#file-output));
- `-jobs <N>`: parallel derivations for `-auto-gen` (default: number of CPUs);
- `-log-level <lvl>`: `silent|error|warn|info|debug` (default: info);
- `-log-format <fmt>`: `pretty|json` (default: pretty);
- `-v`, `-verbose`: shorthand for `-log-level debug`;
- `-no-color`: disable ANSI colour in logs;
- `-case-sensitive`: treat this run as sensitive and hide the values you typed. Phrases, file names and other arguments are replaced by `<hidden>` in logs and error messages. The name refers to a sensitive case, not to letter case;
- `-self-test`: run built-in known-answer tests and exit;
- `-version`: print version, derivation version and runtime, then exit.

Both `-flag` and `--flag` are accepted.

Numbers are plain decimal digits: `016` means 16, as in PyPassGen. Negative values, signs and prefixes such as `0x` are rejected. An option that has no effect in the selected mode is an error rather than being ignored: `-count` belongs to `-mnemonic-only`, `-jobs` to `-auto-gen`, `-words` to the two generating modes, `-password-length` to the modes that produce a password. `-version` and `-self-test` accept only the logging options.

### Examples

1. Generate a password from a mnemonic:
   ```bash
   gopassgen -mnemonic "abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon abandon about" -password-length 16
   ```
   **Output**:
   ```
   ,6UiYsb-haPxbRcv
   ```
   Only the password reaches stdout, so it pipes cleanly:
   ```bash
   gopassgen -mnemonic-stdin < phrase.txt | wl-copy
   ```

2. Auto-generate 2 phrases with 24 words and 32-character passwords:
   ```bash
   gopassgen -auto-gen -phrases 2 -words 24 -password-length 32
   ```
   **Output** (phrases shortened here):
   ```
   Mnemonic 1: scale leopard vanish dolphin ... smart weapon
   Password 1: t(Qd,C)V8,jAi}nXrZNL1CwPhlfuO==8

   Mnemonic 2: father rough shoot follow ... oblige crash
   Password 2: _V=mD9ZT0~._.yZNCDl&X5c9SGh2YCSp
   ```
   Add `-output phrases.txt` to send them to the file only.

3. Generate a French mnemonic with a 20-character password:
   ```bash
   gopassgen -auto-gen -language french -password-length 20
   ```

4. Generate mnemonics only:
   ```bash
   gopassgen -mnemonic-only                                        # 1 phrase, 12 words
   gopassgen -mnemonic-only -count 200 -words 24 -language french  # to stdout
   gopassgen -mnemonic-only -count 5000 -words 24 -output list.txt # -output required above 1000
   ```

5. Verify the binary does what it claims:
   ```bash
   gopassgen -self-test
   ```
   ```
   PASS alphabet     size=88 duplicates=0 rejection-limit=176
   PASS wordlists    7 wordlists verified against SHA-256 digests
   PASS nfkd         ideographic space folds to U+0020
   PASS bip39-seed   PBKDF2-HMAC-SHA512 2048 iterations
   PASS stream       HMAC-SHA512 stream + rejection sampling
   PASS kdf          PBKDF2-HMAC-SHA512 1000000 iterations
   PASS end-to-end   mnemonic to password, PyPassGen 1.3.5 vector
   ```

## Password entropy

Entropy measures password strength in bits (`H = log2(N^C)`, N=88). GoPassGen logs it in DEBUG mode, together with the effective value.
- **Examples**:
  - 12 characters: ~77.5 bits
  - 16 characters: ~103.4 bits
  - 32 characters: ~206.7 bits
- **Guidelines**:
  - `< 64 bits`: Weak
  - `64–80 bits`: Minimum
  - `80–128 bits`: Good
  - `> 128 bits`: Excellent

**The charset bound is an upper bound only.** A password derived from a 12-word mnemonic carries at most 128 bits regardless of its length, because that is all the entropy the phrase has. A 256-character password from a 12-word phrase is still a 128-bit secret. `-verbose` prints both numbers.

## File output

With `-output <file>` the result goes to the file and nothing goes to stdout. `-auto-gen` saves in this format:

```
mnemonic1
password1
mnemonic2
password2
```

`-mnemonic-only` writes one mnemonic per line, and `-mnemonic` or `-mnemonic-stdin` write the password.

- **New files are ordinary files**: mode `0644` minus your umask, the same as the Python original, so other users of the machine can usually read them. Use a stricter umask, such as `umask 077`, or a private directory for real secrets.
- **An existing file is replaced, after a warning** on stderr. It keeps its mode. Replacement happens at the very end: if the run fails or is interrupted, the old file is untouched and no partial file is left behind. The one exception is a file in a directory you cannot write to, such as a single file mounted into a container. No temporary file can be created there, so the file is overwritten directly once all the data is ready. If that last write fails, for example on a full disk, the old contents are lost and the file is left incomplete.
- **Failures are reported.** A full disk or any other write error makes the run exit with code 1.
- **Symbolic links are refused**, so a link cannot redirect secrets or overwrite its target. Links to pipes and devices, such as `/dev/fd/N`, are allowed.
- Missing parent directories are created, and removed again if the run fails.

## Logging

Diagnostics are emitted through the standard library's `log/slog` with structured attributes, so every value is a real key rather than text baked into a sentence:

```console
$ gopassgen -mnemonic-only -count 2 -words 24 -v
2026-08-12 11:59:40.002 - DEBUG - starting language=english version=1.5.0 derivation=pypassgen-1.3.5
2026-08-12 11:59:40.003 - DEBUG - wordlist loaded language=english words=2048
2026-08-12 11:59:40.003 - INFO  - generating mnemonics language=english count=2 words=24
```

`-log-format json` switches to `slog.JSONHandler` for machine consumption, which is the practical mode for large batches:

```console
$ gopassgen -auto-gen -phrases 50 -output pairs.txt -v -log-format json 2>run.jsonl
$ jq 'select(.stats) | .stats.rejected' run.jsonl
```

In JSON mode every line on stderr is a JSON object, including error reports. With `-log-level silent` nothing is printed at all, and only the exit code tells what happened.

Colours are enabled only when stderr is a terminal. Redirecting or piping output disables ANSI codes automatically, and a non-empty `NO_COLOR` or `-no-color` disables them unconditionally. Logs go to **stderr**, generated output to **stdout**, so redirection never mixes the two.

The pretty layout is a small custom `slog.Handler`; attribute and group handling is delegated to `slog.TextHandler`, and the handler is verified against `testing/slogtest`, the standard library's own conformance suite.

## Exit codes

| Code | Meaning |
|------|---------|
| `0` | success |
| `1` | runtime error (invalid mnemonic, I/O failure such as a full disk) |
| `2` | usage error (bad or contradictory arguments) |
| `130` | interrupted by SIGINT/SIGTERM |

## Building

```bash
./build.sh release              # static, stripped, no build id -> build/gopassgen
./build.sh debug                # symbols + DWARF, -N -l, for delve
./build.sh check                # gofmt + go vet + short tests
./build.sh test                 # full suite, including all compatibility vectors
./build.sh verify-reproducible  # rebuild elsewhere, compare SHA-256
./build.sh dist                 # cross-compile every target, zip, checksum
./build.sh clean
```

| | release | debug |
|---|---|---|
| symbol table | stripped (`-s`) | kept |
| DWARF | stripped (`-w`) | kept |
| Go build ID | cleared (`-buildid=`) | cleared |
| VCS stamping | off (`-buildvcs=false`) | off |
| paths | trimmed (`-trimpath`) | absolute |
| optimisation | default | disabled (`-gcflags=all=-N -l`) |
| CGO | disabled (static) | disabled (static) |

Release builds are **reproducible**: the same source tree and Go version produce the same SHA-256 on any machine, in any directory. `./build.sh verify-reproducible` rebuilds in another directory with an empty cache, another time zone and another umask, and compares the results. The zip archives from `./build.sh dist` do not depend on the time zone or umask either, given the same `zip` program.

### What is and is not in a release binary

Removed: the Go build ID, VCS stamping (revision, branch, dirty flag), absolute source paths, the symbol table and DWARF debug information. No timestamps are embedded, and no version string is injected at link time — the version is a source constant, which is what makes the output deterministic.

Still present, because Go has no supported way to remove it: the standard build-info block that `go version -m` reads — module path, the dependency version (`golang.org/x/text`) and build flags such as `GOOS`/`GOARCH`/`CGO_ENABLED`. It contains nothing about the machine that built it. Inspect it yourself:

```console
$ go version -m gopassgen
gopassgen: go1.27.4
        path    github.com/cyberanchor/GoPassGen/cmd/gopassgen
        dep     golang.org/x/text       v0.44.0
        build   -trimpath=true
        build   CGO_ENABLED=0
        ...
$ go tool buildid gopassgen      # empty: no build id
$ strings gopassgen | grep /home # nothing: no paths
```

## Testing

```bash
./build.sh test              # everything
go test -short ./...         # fast, skips the 1M-iteration vectors
go test -race ./...          # concurrency checks
go test -cover ./...         # coverage
```

The suite includes **22 end-to-end password vectors** across all seven languages and lengths 1/12/16/24/32/100/256, plus 35 mnemonic-encoding vectors, 15 seed vectors and 18 validation edge cases — all generated by the Python reference implementation and stored in `internal/passgen/testdata/vectors.json`. **A failing vector means the build is wrong; never edit a vector to make it pass.**

Coverage is 95% of statements. What remains is mostly `main()` and error branches that an intact binary and a healthy file system do not reach.


## Security notes

**Best-effort memory wiping.** Seeds, keys, HMAC state, entropy bits and passwords are zeroed after use, which is why PBKDF2 and HMAC are implemented here instead of taken from libraries that keep key material out of reach. The mnemonic itself is a Go string and cannot be erased, and the Go runtime may hold copies of other data. This cannot be fully solved without locked, non-movable memory.

**A rejected phrase is not echoed.** An invalid mnemonic produces a message naming the *position* of the bad word, never the word itself. `-verbose` reports timings, byte counts and rejection rates in either format, never key material. Tests assert that neither the words of the mnemonic nor the password appear in debug output.

**Command line mistakes show what you typed.** An error about an argument quotes it, which helps to find the mistake. If you paste a phrase without `-mnemonic`, or into the wrong option, that phrase appears on stderr. Add `-case-sensitive` when stderr may be stored, for example in CI logs: values are then replaced by `<hidden>`, wherever the flag stands on the command line.

**Prefer `-mnemonic-stdin`.** Passing a phrase as `-mnemonic` puts it in shell history and makes it visible in `ps` to every user on the machine. On a terminal, `-mnemonic-stdin` does not display what you type, Enter finishes the input and Ctrl-C cancels it.

**Output files use ordinary permissions.** See [File output](#file-output).

**Whitespace is significant.** A mnemonic with a double space, a tab or a leading space is rejected, exactly as in the Python implementation. GoPassGen deliberately does not "repair" such input: trimming it would hash a different byte string and silently produce a different password.

### Known properties of the algorithm

These are inherited from the PyPassGen format and preserved for compatibility. They are documented rather than fixed, because fixing them would change every existing password:

- **Shorter passwords are prefixes of longer ones.** The 12-character password is exactly the first 12 characters of the 32-character one from the same phrase, since both consume the same stream. Leaking a short password reveals the start of a long one.
- **One phrase, one password.** There is no per-site separation: the domain-separation input exists in the format but is always empty. A separate mnemonic per site is the only isolation available.
- **The 1,000,000 PBKDF2 iterations add little.** They stretch a 512-bit seed that is already unguessable; stretching defends low-entropy inputs, and this input is not one. Real strength equals the mnemonic's entropy: 128 bits for 12 words, 256 for 24.
